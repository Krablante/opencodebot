# OpenCodeBot

**Сессии OpenCodez в Telegram без переноса рабочей среды из OpenCodez.**

OpenCodeBot читает API и поток событий OpenCodez и показывает видимую работу сессии в топике Telegram-форума. С телефона можно создать сессию, отправить запрос, ответить на вопрос агента и получить финальный результат. Сессии, идентификаторы сообщений, инструменты и веб-интерфейс остаются в OpenCodez; бот даёт компактный второй способ управлять работой.

[Русский](README.ru.md) · [English](README.md) · [Документация](docs/ru/README.md) · [Лицензия MIT](LICENSE)

## Как это устроено

```text
API OpenCodez + один поток событий на сервер
                   ↓
          OpenCodeBot (Node.js)
                   ↕
          Топики Telegram-форума
```

Один топик соответствует одной основной сессии OpenCodez. Ответы приходят готовыми блоками; в полном режиме инструменты показаны короткими статусами. Скрытые рассуждения, сырые аргументы инструментов и дочерние сессии не попадают в зеркало. Привязки, отметки доставки и входящие обновления Telegram переживают перезапуск. Очередь запросов `/q` живёт только в памяти.

Расшифровку речи, озвучку финального ответа и шлюз для отправки файлов в выбранный топик можно включить отдельно. WireGuard для удалённого браузера и локальный Telegram Bot API тоже необязательны.

## Запуск

Нужны Node.js **22+**, работающий сервер OpenCodez, токен бота Telegram и ваш числовой Telegram user ID. Для Linux, macOS и Windows рекомендуем Docker Compose; напрямую через Node.js бот тоже работает.

```bash
git clone https://github.com/Krablante/opencodebot.git
cd opencodebot
npm run init-config
```

Скопируйте `token.env.example` в игнорируемый `token.env`: на Linux/macOS — `cp token.env.example token.env`, в PowerShell — `Copy-Item token.env.example token.env`. Заполните `OPENCODEBOT_TOKEN`, `OPENCODEBOT_ALLOWED_USER_IDS` и пароль API OpenCodez. В созданном `servers.json` укажите HTTP-адрес сервера, доступный **из окружения бота**. Для контейнера `127.0.0.1` означает сам контейнер; используйте доступный адрес хоста или `host.docker.internal`. Если `/new` должен создавать сессии в определённом каталоге, задайте абсолютный `home`. Перед приёмом файлов настройте доступные для записи пути.

Рядом лежит созданный `config.local.json`. Проверьте настройки `telegram`, `defaultPrompt` и `opencode`. В примере автоматические обновления и дополнительные провайдеры отключены. Первое сообщение от разрешённого пользователя может привязать форум, пока включён `allowChatBootstrap`; затем запишите `telegram.chatId` и отключите начальную привязку.

Для Docker Compose создайте записываемый каталог `state`: `mkdir -p state` на Linux/macOS или `New-Item -ItemType Directory -Force state` в PowerShell. Команда развёртывания требует **чистый Git checkout**, помечает образ ревизией и проверяет живой сервис:

```bash
npm run deploy:bot
docker compose logs -f opencodebot
```

Для прямого запуска выполните `npm start`. Не запускайте его одновременно с контейнером, который опрашивает Telegram тем же токеном. [Docker](docs/ru/docker.md) описывает монтирования, пути хоста, локальный Bot API и обновление, а [конфигурация](docs/ru/config-runtime.md) — файлы и настройки серверов.

## Работа с ботом

Откройте закреплённую панель в General командой `/menu`. Команда `/new [server] [profile] [dir:<path>] [title]` создаёт топик; первый запрос в нём создаёт сессию. В привязанном топике `/q` ставит запрос в очередь, `/kill` останавливает выполнение, `/reset` начинает новую сессию в том же топике и сохраняет старую, `/context` выгружает недавние ходы. Ответ на ранний запрос в Telegram откатывает именно тот ход OpenCodez. `/mode economy` скрывает обычные сообщения об инструментах, `/mode full` возвращает короткие статусы. Когда настроен шлюз, `/artifacts_here` выбирает единственный топик для доставки файлов.

Полные правила и команды собраны в [сценариях Telegram](docs/ru/telegram-workflow.md). У [озвучки](docs/ru/final-voice.md), [расшифровки речи](docs/ru/config-runtime.md#расшифровка-речи) и [артефактов](docs/ru/artifact-gateway.md) есть отдельные инструкции.

## Эксплуатация и разработка

`npm run check` проверяет синтаксис, `npm test` — важные контракты, `npm run smoke` — локальные интеграционные сценарии без сообщений в Telegram. `npm run health:live` проверяет работающий Compose-сервис, доступ к Telegram и обязательные API OpenCodez. При изменении сервисов Compose используйте `npm run deploy:all`. Для работы бота не нужен отдельный CI; границы исходников, состояния и обновляющего механизма описаны в [разработке](docs/ru/development.md) и [самообновлении](docs/ru/self-update.md).
