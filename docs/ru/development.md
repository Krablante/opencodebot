# Разработка и проверка

[Русский](development.md) · [English](../en/development.md) · [Указатель](README.md)

Исходники уже нельзя полезно читать одним проходом. Начните с пользовательского действия: где принято обновление Telegram или событие OpenCodez, какая часть изменяет состояние, кто отправляет ответ. Это помогает менять ровно тот поток, который отвечает за поведение.

## Зоны ответственности

`src/main.mjs` собирает приложение и завершение. `telegram-polling.mjs` получает обновления, ведёт независимые упорядоченные очереди топиков и ограничивает параллелизм. `telegram-inbox.mjs` надёжно фиксирует приём до подтверждения Telegram. `commands.mjs`, `control-menu.mjs` и `topic-lifecycle.mjs` отвечают за команды, панель и жизненный цикл топика. `prompt-routing.mjs` ведёт запросы, файлы, откат и память очереди; `attachments.mjs` обслуживает временные загрузки.

`opencode.mjs` — API и поток событий OpenCodez, `session-reconcile.mjs` — обработка событий и догоняющее восстановление по курсорам. `internal-sessions.mjs` задаёт границу видимости, `logical-turn.mjs` связывает ход через compaction/replay. `render.mjs` и `render-side-effects.mjs` доставляют видимый текст и связанные действия, `final-notifications.mjs` — личные уведомления. `state.mjs` хранит привязки и отметки зеркала; `telegram.mjs` инкапсулирует Bot API. Дополнения живут в `speech/`, `final-voice.mjs`, `artifacts-gateway.mjs` и `update-manager.mjs`.

Один `/global/event` либо `/event` на сервер достаточен для выбранной области зеркалирования. Текстовые SSE delta должны быть привязаны к видимой текстовой части сообщения ассистента; reason/tool payload нельзя отдавать в Telegram. Здоровый live поток не должен запрашивать историю после каждого сообщения. `404` одной сессии удаляет только её привязку; сетевые, `408`, `429` и `5xx` ошибки участвуют в общем откладывании запросов к серверу. Финальные уведомления требуют точный ID доставленного финала.

`compaction-reminders.mjs` отправляет напоминания после автоматического компакта и подтверждает их сохранение через
существующую сверку с бэкендом. Служебные метаданные связывают повтор с исходным ходом в `logical-turn.mjs`, в том числе
при наличии медиа. Состояние содержит только общую настройку `/reminder` и ограниченные отметки доставки;
текст и файлы берутся из истории OpenCodez.

## Локальные проверки

Персональными черновиками тем и профилей управляет `launch-menu.mjs`, preferences и однократным импортом — `user-settings.mjs`, подключениями — `setup.mjs`. Ввод ключей фильтруется до записи inbox, включая старые незавершённые обновления. Создание темы находится в `topic-lifecycle.mjs`; мастер и быстрые команды используют одну логику и идентификатор запроса. Автоматическое обновление меню берёт статусы из SSE; явное открытие и Refresh запрашивают backend.

`node scripts/preview-ui.mjs /tmp/opencodebot-ui` формирует HTML-превью и страницы гайда для печати. При изменении текста или иллюстрации пересобери PDF в `assets/` и проверь их через vision. Для локального шрифта с кириллицей доступны `OPENCODEBOT_PREVIEW_FONT` и `OPENCODEBOT_PREVIEW_BOLD_FONT`. Prepared-message API Telegram проверяет настоящий парсер Rich HTML и кнопок без публикации превью. Отправку, изменение и удаление ephemeral-экрана нужно отдельно пройти на Bot API 10.3+.

```bash
npm run check
npm test
npm run smoke
```

Синтаксическая проверка написана на Node.js и работает в Linux, macOS и Windows. Тесты держат небольшое число важных контрактов; smoke проверяет маршрутизацию, восстановление, ограничения файлов и конфигурацию без второго poller и без записи в рабочий чат. Не добавляйте тесты на каждую вспомогательную функцию; при существенном риске лучше расширить центральный сценарий. Для правок API и Telegram-доставки используйте одноразовые данные и проверяйте реальные пограничные ветки: отказ JSON, прерванный поток, длинный текст, очередь при простое и ошибке, перезапуск с незавершённым inbox. Не запускайте другой процесс с рабочим токеном Telegram.

Локальный `npm start` читает `config.local.json`; `npm run init-config` создаёт его без перезаписи. В PowerShell те же npm-команды. Docker использует `docker compose build` и `docker compose run --rm opencodebot npm run check`. Работающий Compose-сервис проверяется `npm run health:live`; это read-only проверка опроса Telegram, восстановления сессий и обязательных backend API, без отправки сообщений или файлов.

## Развёртывание

Исходники, образ и работающий контейнер — разные поверхности. При согласованном обновлении сервиса применяйте `npm run deploy:bot` для одного бота либо `npm run deploy:all` при изменении Compose-сервисов. Команда требует чистое дерево Git, ставит зависимости по lockfile, проверяет синтаксис, собирает образ с полным SHA, пересоздаёт контейнер и запускает `health:live`. После этого проверьте недавние логи `docker compose logs --since=2m opencodebot`. Изменение источника плагина или skill ещё требует отдельного развёртывания их **установленных** копий в OpenCodez.

Не складывайте журналы, токены, файлы Telegram или состояние рядом с кодом. Миграции хранилища и обработка незавершённого inbox описаны в [конфигурации](config-runtime.md#сохранение-и-восстановление), хостовой runner — в [самообновлении](self-update.md). Делайте границы модулей по ответственности и проверяемому потоку данных, без новых адаптеров ради симметрии каталогов.
