# Разработка

[English](../en/development.md) · [Русский](development.md) · [Все языки](../README.md)

OpenCodeBot запускается как ES-модули Node.js. Компилятора, сборщика и прикладного фреймворка нет. Два пакета mdast разбирают CommonMark и сохраняют форматирование; HTTP, потоки, файлы и процессы обслуживают API Node. `package-lock.json` должен оставаться в Git. Перед изменением событий и восстановления прочитай [архитектуру](architecture.md).

## Карта исходников

Каталоги отражают реальные границы. `src/config/` нормализует конфигурацию, `src/i18n/` хранит каталоги интерфейса, `src/speech/` занимается распознаванием, `src/artifacts/` содержит разбор и форматирование шлюза. Корневые модули владеют связанными процессами бота. Каталог для каждого мелкого помощника здесь усложнил бы навигацию.

| Область | Владелец |
| --- | --- |
| Запуск и сборка частей приложения | `src/main.mjs` |
| Транспорт и входящие обновления Telegram | `telegram.mjs`, `telegram-polling.mjs`, `telegram-inbox.mjs`, `telegram-rich-message.mjs` |
| Отправка промптов, буферы и очередь | `prompt-routing.mjs`, `prompt-queue.mjs`, `multipart-prompts.mjs`, `attachments.mjs` |
| Транспорт OpenCodez и восстановление | `opencode.mjs`, `session-reconcile.mjs`, `backend-backoff.mjs`, `single-flight.mjs` |
| Логические ходы и компакция | `logical-turn.mjs`, `compaction-reminders.mjs`, `context-export.mjs` |
| Жизненный цикл и названия тем | `topic-lifecycle.mjs`, `topic-titles.mjs` |
| General, личные карточки и setup | `control-menu.mjs`, `launch-menu.mjs`, `setup.mjs` |
| Предпочтения и постоянное состояние | `user-settings.mjs`, `state.mjs` |

`plugins/opencodebot-artifacts/` — отдельно устанавливаемый плагин агента со своим пакетом. `skills/telegram-artifact-send/` — полный сопутствующий skill. Развёртывание бота не устанавливает их в OpenCodez. `scripts/` содержит команды эксплуатации и общий smoke, `test/` — несколько важных контрактов API/состояния. В `assets/` лежат гайды и словарь с атрибуцией.

## Проверки

Для небольшой правки начни с синтаксиса и ограниченного ручного сценария. Для общего состояния, транспорта и доставки используй существующие проверки. Не создавай тестовый файл для каждого помощника или ветки форматирования.

```bash
npm ci
npm run check
npm run docs:check
npm test
npm run smoke
```

Те же команды работают в PowerShell. `check` обходит JavaScript через Node, без shell glob. Небольшие тесты защищают разбор запуска, payload модели/System, очередь, вопросы и восстановление/контекст. Smoke проверяет конфигурацию, порядок событий, таймауты, изоляцию входа, вывод, состояние, уведомления, голос и файлы на одноразовых данных. Без конфигурации он использует публичный пример и пропускает живые подключения.

`node scripts/smoke.mjs /absolute/config.json` дополнительно делает проверки Telegram/OpenCodez только для чтения и проверяет локальное монтирование FILES. Никогда не запускай второй poller с production-токеном. `npm run health:live` проверяет действующий процесс Compose; `smoke:live` — его совместимое имя.

GitHub Actions выполняет одну задачу для push в `main` и pull request: установка закреплённых зависимостей, синтаксис, документация, небольшие тесты и изолированный smoke. Проверка документации сверяет языковые наборы файлов, ссылки/якоря, команды npm и примеры JSON. У задачи нет ключей развёртывания, она не отправляет сообщения Telegram. Релиз и живые проверки остаются действиями оператора.

## Проверяй поведение

Для промптов и восстановления нужны обычный запрос при idle, выпуск очереди после финальной доставки, повтор неудачного запуска, отсутствующая сессия и рестарт с изолированным состоянием. Для inbox перекрой две темы между полученными пачками, задержи один обработчик, заверши события в разном порядке и проверь заполнение/ошибки диска. Порядок темы и надёжность приёма должны сохраняться.

Для файлов отклони большой вход до скачивания, проверь фактический остаток лимита, передай целый файл потоком, оборви передачу и повтори имя в FILES. Сверь байты и очистку подготовки. SSH проверяй в одноразовой папке каждой затронутой платформы; мок вызова процесса не проверяет удалённую оболочку.

Для форматирования проверь локальные пути, пробелы/скобки/backticks, reference links, картинки, вложенные списки и код. `savePreparedInlineMessage` с `InputRichMessageContent` проверяет настоящий парсер Rich Messages, ничего не публикуя. Настоящие send/edit/delete и превью размера телефона всё равно нужны для транспорта и визуала. Prepared-сообщение не доказывает вид каждого клиента.

## Интерфейс и гайды

```bash
node scripts/preview-ui.mjs /tmp/opencodebot-ui
```

Команда создаёт переносимые HTML-превью и страницы для печати из реальных renderers меню. `OPENCODEBOT_PREVIEW_FONT` и `OPENCODEBOT_PREVIEW_BOLD_FONT` выбирают локальные шрифты с кириллицей. Текст гайда находится в `src/user-guide.mjs`; после изменения текста/иллюстраций пересоздай `assets/guide-en.pdf` и `assets/guide-ru.pdf` и осмотри отрисованные страницы.

Пользовательская документация организована как `docs/<код-языка>/<тема>.md`; [индекс языков](../README.md) перечисляет доступные версии. Добавь каталог с теми же именами тем, обнови навигацию и синхронизируй смысл одним изменением. Переводы README — входные страницы. Каталоги интерфейса расширяются по отдельным правилам [языка интерфейса](interface-language.md).

## Изменение и релиз

Состояние процесса и его побочные действия должны оставаться у владельца. Выделяй помощник, когда это отделяет реальную обязанность. Избегай параллельных маршрутизаторов, копий восстановления и новой зависимости ради замены небольшой стабильной функции. OpenCodez владеет ID сообщений и историей. Рабочие данные хранятся вне Git.

Используй короткие Conventional Commit. Карточка обновления превращает `feat:`, `fix:` и `perf:` в заметки для пользователя, а технические коммиты группирует. Перед публикацией проверь status/diff, выполни соразмерные проверки, обнови связанные языковые версии и сверь версию пакета.

Путь релиза — [развёртывание Compose](docker.md#run), живая проверка и сверка ревизии. `OPENCODEBOT_BUILD_SHA` и OCI label образа должны совпасть с закоммиченным кодом. Публикуй GitHub-релиз для проверенной ревизии. Изменения Compose/обработчика хоста требуют ручного развёртывания; плагин/skill — отдельного обновления установленных копий. Эти границы описаны в [обновлениях](self-update.md).
