# Работа в Telegram

[English](../en/telegram-workflow.md) · [Русский](telegram-workflow.md) · [Все языки](../README.md)

В General создавай темы, выбирай профили и меняй настройки. В рабочем топике разговаривай с агентом. Каждая тема следует одной активной сессии OpenCodez; сессия и её история остаются в OpenCodez.

<a id="topics"></a>
## Темы

`/new` открывает мастер темы в обычной карточке чата. До создания видны конкретные профиль, провайдер/модель, reasoning, сервер и папка. Название по умолчанию — старинное или образное русское существительное со случайным регистром; «Другое слово», «Название» и «Настройки → Случайные названия» управляют выбором. Первый обычный промпт создаёт backend-сессию. Сохраняются именно показанные настройки, даже если именованный профиль изменился до первого промпта.

При нескольких серверах добавляется управляемый суффикс ` (<serverID>)`. Собственные/случайные названия переживают изменения заголовка OpenCodez. Ручное переименование Telegram становится принадлежащим теме и обновляет сохранённую историю. `/reset` оставляет название и при смене сервера меняет только суффикс. При одном сервере суффикса нет. Значок выбирается случайно, если Telegram предоставляет доступные stickers.

Закрытие или удаление темы останавливает её зеркало, очищает очередь, восстановление и ожидающий запуск. Backend-сессия и отключённая история сохраняются. Если нужно остановить выполнение, сначала используй `/kill`. «Недавние» проверяет удаление коротким тихим обычным сообщением с немедленным удалением; сохранённое название не переустанавливается. У Telegram нет списка/чтения тем или события удаления. Сеть, права и лимиты не доказывают удаление. Открытие проверяет максимум 18 кандидатов, пока не найдёт шесть тем; при большом числе удалений следующая «Обновить» продолжает очистку.

Внутренние дочерние сессии и точное нормализованное имя `opencode-see delegate` не создают рабочие темы. Старые записи бота удаляются без удаления тем Telegram.

<a id="commands"></a>
## Команды

Частые действия видны в slash-меню Telegram. Setup и расширенные команды принимаются при ручном вводе. Bot API не имеет меню команд отдельно для топика.

| Команда | Действие |
| --- | --- |
| `/menu` | Перенести закреплённую панель General в новое сообщение |
| `/new` | Открыть создание темы |
| `/new [server] [profile] [dir:<path>] [title]` | Создать напрямую; сессия запускается первым промптом |
| `/session` | Сервер, копируемый ID, статус, сохранённые настройки и отдельные назначения файлов/аудио |
| `/q <prompt>`, `/q status`, `/q delete N` | Поставить задачу, посмотреть очередь или убрать пункт |
| `/kill` | Остановить сессию и отбросить очередь/незавершённый составной промпт |
| `/compact` | Уплотнить существующую idle-сессию штатным механизмом OpenCodez |
| `/reset [profile] [server]` | Начать заново в этой теме, сохранив предыдущую сессию |
| `/context [N]`, `/set_context N` | Экспортировать недавние ходы; сохранить личный выбор, 1–10 |
| `/export` | Скачать дословные промпты и финальные ответы текущей сессии одним Markdown-документом |
| `/reminder [on\|off]` | Посмотреть/изменить напоминания после автоматической компакции посреди работы |
| `/speak` | Ответить на текст и получить одну голосовую сводку |
| `/help`, `/start`, `/setup` | Гайд, General или подключения |

Дополнительные команды: `/mode full|economy`, `/mirror_on`, `/mirror_off`, `/lang eng|ru`, `/notify_on`, `/notify_off`, `/notify_status`, `/debug_on`, `/debug_off`, `/debug_status`, `/update`, `/artifacts_here`, `/sounds_here`, `/sounds_off`, `/sounds_status` и `/tts`. Обычные настройки находятся в General; [озвучке](final-voice.md) и [обновлениям](self-update.md) посвящены отдельные справочники.

### Создание напрямую и сброс

`/new` разбирает сервер, затем профиль, затем необязательный `dir:`/`directory:` и название. Неизвестные слова остаются названием: опечатка не выбирает другой сервер/профиль. Для названия, совпадающего с заданным именем, сначала укажи сервер и профиль. Аргумент пути с пробелами целиком заключай в кавычки.

```text
/new Проверить загрузки
/new workstation Проверить релиз
/new sol Исправить парсер
/new workstation sol Проверить загрузки
/new workstation sol "dir:/workspace/My Project" Проверить загрузки
/new workstation sol sol
/reset
/reset solm
/reset workstation
/reset solx workstation
```

Без аргументов reset наследует профиль/сервер/папку. Именованный профиль берётся из актуальных предпочтений; удалённый заменяется сохранённым снимком темы. Один аргумент выбирает профиль или сервер, два — профиль, затем сервер. Неоднозначные, неизвестные и лишние аргументы отклоняются до остановки и изменений. Тот же сервер сохраняет папку; другой получает свой default после проверки. Неудачный abort оставляет активную привязку. Успех атомарно отключает старую сессию и сохраняет ожидающий запуск. Повторный reset ожидающей темы не создаёт лишнюю сессию. General, FILES, AUDIO и непривязанная ручная тема не сбрасываются.

`/session` различает активную, ожидающую, отключённую, удалённую и недоступную сессию. У ожидающей нет нового ID; прежний показан только в деталях. Служебные темы показывают назначение без старых настроек агента. Неизвестное имя назначения обозначается явно. Чтения backend идут параллельно с пределом пять секунд, поэтому offline-сервер не замораживает команду.

<a id="prompts"></a>
## Промпты

Пиши обычный текст в рабочей теме. Части текста около предела Telegram кратко собираются в один промпт. Файлы с подписью идут вместе с текстом; без подписи ждут текст того же пользователя/топика. Rich Messages сохраняют читаемый текст и поддерживаемые фотографии в том же маршруте. Количество/размеры проверяются до скачивания и по фактическому остатку лимита.

Приём показывает одно короткое сообщение. С третьей попытки провайдера оно становится редактируемым предупреждением; вывод/idle убирает его. Отклонённый промпт получает понятную ошибку. Если backend-сессия удалена, тема становится ожидающей и просит повтор; бот не отправляет замену молча. ID сообщений всегда создаёт OpenCodez.

<a id="reply-to-rewind"></a>
### Ответ для возврата к ходу

Ответь на прежний пользовательский промпт Telegram, чтобы заменить его точный ход OpenCodez. Связь должна относиться к той же активной сессии/теме и не заменённой ветке. Ответ на промпт до reset или другой темы отклоняется; посторонний reply остаётся обычным промптом. Старые промпты без постоянной связи ID нельзя откатить.

Бот отбрасывает последующую очередь, при необходимости останавливает запуск, ждёт idle и просит OpenCodez выполнить revert. Ответ backend должен подтвердить сессию и точный ID пользователя до изменения связей и отправки замены. Одно сообщение меняется с «Отменяю…» на подтверждение или объясняет неудачу проверки/отправки. Рабочие файлы и историю восстанавливает сам OpenCodez.

<a id="queue"></a>
## Очередь

В длинном текстовом промпте достаточно одного `/q` в начале. Бот собирает продолжения от того же пользователя в той же теме и принимает одну целую задачу после двух секунд без следующей части. Даже короткая первая часть сохраняет режим очереди для продолжений. Новый `/q` начинает отдельную задачу; другая команда завершает сборку, а kill/reset её сбрасывают. Команда чтения `/export` не трогает накопленный ввод. Неизвестный текст с начальным слешем, например путь к файлу, остаётся частью ожидающего промпта. Предел сборки — 20 частей и 120 000 символов. При превышении задача целиком отклоняется с объяснением; обрезанный промпт не отправляется.

Rich Messages принимают `/q` в начале первого текстового абзаца или заголовка, в том числе в жирном тексте и в форме `/q@botname`. Последующие абзацы, списки, таблицы, код и поддерживаемые фотографии остаются вместе в задаче очереди. `/q` внутри блока кода или цитаты считается содержимым промпта.

После сборки `/q` проверяет backend при приёме. Idle-задача запускается сразу, занятой запрос ждёт в памяти вместе с файлами. Выпуск требует idle и доставленного финала/уведомления, в любом порядке. Восстановление истории восполняет пропущенные сигналы. Вопросы и незавершённая ручная компакция удерживают очередь. Ошибка запуска очищает ожидающее и перечисляет краткие подписи; повторные события не выпускают два промпта.

Пределы: 20 ожидающих задач на сессию, 100 всего и 64 МиБ текста/встроенных файлов. Переполнение отклоняется с просьбой повторить; `/q delete N` освобождает место. Kill, reset, закрытие/удаление и перевод в FILES/AUDIO сбрасывают буферы текста/вложений всей темы, включая ожидающий ввод других операторов. Рестарт сбрасывает очередь и буферы, сохраняя backend-историю. [Гарантии хранения](config-runtime.md#paths-and-state) объясняют отличие постоянного приёма входа от этой границы.

## Компакция и контекст

Если после перезапуска сервера или потери события запуск остановился без финального ответа, бот предупреждает об обрыве в рабочей теме. Этот случай проверяют восстановление соединения и существующая проверка раз в минуту, без перечитывания завершённых историй на каждом проходе. Для подтверждения исхода сервер должен быть доступен. `/session` показывает для свободного сервера **«Не выполняется»**: это активность, а результат задачи или предупреждение об обрыве появляются в разговоре.

`/compact` нужен существующей idle-сессии с историей и известной моделью. Он работает в фоне и ставит следующие промпты в очередь. Kill/reset/rewind отменяют активную операцию бота. Успех даёт один `🗜️ сессия скомпактирована`; внутренний summary скрыт. Маркер появляется и при автоматической или веб-компакции.

Напоминания изначально включены. Автокомпакция во время работы восстанавливает исходный запрос/вложения из OpenCodez и добавляет английский `REMINDER:` с просьбой сохранить прогресс и последующие уточнения. Уведомление `🔁 Промпт продублирован в виде напоминания` появляется после подтверждения приёма. Если OpenCodez сам повторил запрос, в том числе после сжатия перед началом запроса (pre-turn), бот подтверждает сохранённый повтор и показывает то же уведомление, не отправляя ещё одну копию. Одного завершённого сжатия недостаточно для подтверждения повтора.

Повтор не зеркалируется как новый человеческий запрос; уведомление отмечается в состоянии, чтобы не повторяться при обычном восстановлении и рестарте. Ручная компакция, остановленные запуски и отключённые темы не получают дополнительного напоминания от бота; уже подтверждённый серверный повтор можно отметить и после завершения работы. Повторы следуют исходному запросу, не вкладывая напоминания друг в друга. Пути больших файлов должны оставаться доступными.

`/context` экспортирует три недавних хода основной сессии либо выбранные 1–10. Завершённый ход содержит исходный запрос и финал. Прерванный/замещённый — запрос и пронумерованные видимые заметки; активный незавершённый ход исключается. Компакция/replay/reminder остаются частью исходного логического хода. Reasoning, инструменты и внутренние summaries исключены.

Контекст приходит свёрнутыми блоками кода Rich Message, экранированными и разбитыми без обрезки. Общий предел — 240 000 символов, части меньше 30 000 UTF-8 байт. При неудаче последующей доставки прошлые части удаляются по возможности, остаётся короткая ошибка. **Свёрнутый контекст доступен всем участникам группы**, это не приватное хранилище. Бот сохраняет только числовую глубину.

<a id="session-markdown-export"></a>
## Экспорт сессии в Markdown

Отправь `/export` без аргументов в рабочем топике. Команда читает всю текущую сессию OpenCodez и присылает один документ `.md` в тот же топик. Она не отправляет промпты, не запускает накопленный ввод, не останавливает работу, не сжимает и не меняет сессию.

В файле идёт дословный твой промпт, затем дословный финальный текстовый ответ нейросети, затем следующая пара — по порядку промптов. Реальные повторы пользователя остаются отдельными. Заголовки обозначают номер пары и роль; Markdown внутри исходного текста не может закрыть ограждение блока. Несколько исходных текстовых частей остаются отдельными буквальными блоками с сохранением содержимого и пробелов.

Reasoning, комментарии, инструменты, промежуточные ответы, автоматические replay/reminder и сводки компакции исключены из завершённых пар. Финал — завершённое сообщение ассистента с `finish=stop`, без ошибки и признака summary. ID replay/reminder связывают его с исходным человеческим промптом; совпадение текста не удаляет твои повторы.

Запрос без финала остаётся в основной последовательности с явной пометкой. Его видимые progress notes, если они есть, идут только отдельным разделом в конце, с номером запроса и пометкой **не финальный ответ**. Заметки завершённых пар не включаются. Отменённый хвост после rewind и задачи очереди, ещё не принятые backend, не относятся к текущей выгружаемой истории.

История читается страницами; reasoning, вывод инструментов и данные вложений отбрасываются по мере чтения. Документ записывается и отправляется из приватного временного файла без второй полной копии в памяти; успешная операция и ошибки удаляют файл. Остатки после аварии убирает существующая очистка spool через 24 часа. Если полный документ превышает лимит используемого Telegram API, команда сообщает об этом и не отправляет обрезанный файл. Справочник в General и оба PDF описывают то же содержимое.

<a id="questions"></a>
## Вопросы

Вопрос с одним выбором имеет кнопку на каждый вариант. Нажатие отвечает backend, убирает клавиатуру и обновляет сообщение. Для своего ответа ответь текстом на сообщение вопроса. Несколько вопросов/множественный выбор ведут в OpenCodez. Ответ в веб-интерфейсе закрывает управление и в Telegram.

Пропущенные вопросы восстанавливаются существующим пятнадцатисекундным reconcile и после SSE-переподключения, с общим backoff и single-flight запроса. Они не завершают ход очереди. Личные уведомления о блокирующих вопросах идут заданным получателям даже при выключенных уведомлениях о финалах.

<a id="final-notifications"></a>
## Личные уведомления

Открой личный чат бота один раз. Финальные уведомления персональные; `/notify_on`, `/notify_off` и `/notify_status` относятся только к вызвавшему их пользователю. Блокирующие вопросы и ошибки всё равно приходят. Финальный DM отправляется после появления точного Telegram ID ответа, с постоянной проверкой повторов на получателя. Восстановление старой истории не рассылает прошлые финалы.

DM ведёт к точному ответу и показывает актуальные имя/значок темы, длительность логического хода, фактические модель/reasoning, суммарные input/output/cache токены, цитату исходного запроса, завершённый список задач и компактные инструменты/изменённые файлы. Ответ не повторяется. Дочерние сессии исключены из учёта. `/debug_on` добавляет общие timing/TPS/инструментальные подробности, `/debug_off` убирает. TPS измеряет полное время шага модели за вычетом известных интервалов инструментов, а не пиковую скорость потока.

## Файлы и аудио

FILES получает артефакты агента и сохраняет пользовательские файлы на выбранном сервере. Пустая подпись берёт default; `workstation first, backup` задаёт сервер и имена по порядку. Существующие файлы молча не заменяются. [Доставка артефактов](artifact-gateway.md#user-dropped-files) описывает пути, расширения и установку.

При включённом распознавании голосовые в обычных темах, кроме FILES, дают только расшифровку. AUDIO также принимает аудиофайлы/документы. Длинный текст разбивается без потерь на обычные копируемые Mono-сообщения; метаданные идут после последней части. Отправь расшифровку текстом, чтобы передать агенту. `/sounds_off` убирает отдельную тему, сохраняя распознавание обычных голосовых. Озвучка финалов отдельно настраивается в [Final Voice](final-voice.md).

<a id="mirror"></a>
## Зеркало

Economy — исходный режим: видимый прогресс, финалы и ошибки, без обычных инструментов. Full добавляет компактный сворачиваемый статус инструментов. Оба скрывают reasoning, сырые аргументы, служебный учёт и дочернюю активность; оба показывают короткий заголовок запуска subagent. Завершённые текстовые блоки отправляются однократно, без редактирования на каждый токен. События удаления частей при откате убирают старый прогресс по возможности.

Веб-промпты сохраняют буквальный текст, переносы строк, пустые строки и отступы. Короткие запросы идут обычными сообщениями, длинные — блоками абзацев Rich Message с отдельным заголовком. Markdown и HTML внутри промпта остаются буквальным текстом. При превышении бюджета сообщения в 32 000 символов текст делится без удаления пробелов и переносов; отказ Rich даёт все обычные части. Telegram-промпты связываются с каноническими backend ID и не повторяются как веб-ввод.

В ответах агента локальные Markdown-ссылки/картинки превращаются в читаемые пути; HTTP-картинки получают одну попытку ссылками при отказе фото. Другие ошибки формата используют обычный текст; транспортные ошибки передаются восстановлению. Финальный `finish=stop` получает `🏁`, исходный пользовательский промпт закрепляется.

<a id="telegram-update-isolation"></a>
## Независимость входящих тем

Темы сохраняют порядок ввода, пока следующие пачки Telegram продолжают приходить. На backend работают два обработчика; управление/аудио/FILES имеют отдельные группы. Первичная привязка чата последовательна. Приём записывается и синхронизируется до подтверждения через `getUpdates(offset)`; завершения исключают отдельные события, включая разный порядок между темами.

Неудачная операция с доставленной ошибкой завершается. Без доставленного уведомления она повторяется в своей теме с задержкой 2,5–30 секунд, освобождая слот группы. Inbox останавливает приём на 1 000 событий или 16 МиБ, с одной последней пачкой сверх лимита байтов. Завершение сохраняет ожидающие события. Авария после действия до отметки завершения может повторить его; очереди/медиабуферы имеют отдельные ограничения рестарта.

<a id="reconcile"></a>
## Восстановление

Пропуски событий восстанавливаются ограниченным чтением истории. Обнаружение корневых сессий использует выбранную область; старт отмечает старые сессии без публикации истории. Курсоры и небольшие проверки неизменившихся сессий ограничивают запросы. После переподключения проверяются недавние привязки и очереди, по пять страниц на привязку. [Архитектура](architecture.md#recovery-and-limits) объясняет координацию, сроки и оставшиеся компромиссы.
