# Обновления

[English](../en/self-update.md) · [Русский](self-update.md) · [Все языки](../README.md)

Обычный путь — `git pull --ff-only` и `npm run deploy:bot`. Необязательное подтверждение Telegram автоматизирует такое же обновление только бота через фиксированный обработчик Linux-хоста. OpenCodez, установленные plugins и skills оно не обновляет и не перезапускает.

## Конфигурация

Расписание изначально выключено. `/update` проверяет сразу, не включая и не сдвигая расписание. Автопроверке нужны явные время и IANA-пояс:

```json
{ "updates": { "enabled": true, "repository": "Krablante/opencodebot",
  "branch": "main", "checkAt": "07:00", "timeZone": "Europe/London" } }
```

Планировщик проверяет раз в минуту и сохраняет последнюю календарную дату выбранного пояса. Рестарт после назначенного времени выполняет пропущенную проверку. Скрытого расписания в коде нет. Ревизия берётся только из `OPENCODEBOT_BUILD_SHA` образа; отсутствие/неверное значение отключает проверки до правильно подписанного развёртывания.

## Карточка Telegram

Предложение показывает текущую/целевую ревизии, заметки и сравнение GitHub. «Обновить и перезапустить» подтверждает именно показанную версию. «Не сейчас» скрывает её до следующего дня расписания; без расписания закрывает только ручное предложение.

Заметки берутся из точного диапазона Git: `feat:`, `fix:`, `perf:` дают пользовательские группы, остальные объединяются как техническая работа. Видно максимум восемь пунктов. Полная публикация остаётся в GitHub Releases, отдельный дублирующий changelog не нужен.

Та же карточка проходит проверку, установку зависимостей, синтаксис, сборку, рестарт и живую проверку. Сохранённые ID запуска/сообщения дают новому процессу завершить старую карточку. Хост останавливается через 30 минут; бот признаёт пропавший прогресс прерванным через 35 и освобождает повтор.

Compose и `scripts/apply-update.mjs`/`scripts/install-update-runner.mjs` требуют ручного обновления. Карточка показывает пути, нужный `deploy:bot`/`deploy:all` и повтор установки runner при необходимости. Изменения plugin/skill показывают отдельный шаг для установленных копий.

## Граница хоста

У контейнера нет Docker socket и исходников. Подтверждение записывает UUID и две полные Git-ревизии в атомарные файлы тома состояния:

```text
state/updates/request.json → user systemd.path → scripts/apply-update.mjs
state/updates/status.json  ← фиксированный runner ← deployment/health бота
```

Обработчик проверяет чистоту исходников, origin, принадлежность ветке и fast-forward. Команды получают фиксированные массивы аргументов; callback никогда не становится shell-кодом. Он ставит зависимости, проверяет синтаксис, сохраняет прежний образ для отката, собирает подтверждённую ревизию, пересоздаёт только бота и запускает health.

При неудаче замены/health возвращается прежний образ с проверкой. Исходники могут остаться обновлёнными: образ определяет действующую ревизию, повтор не требует разрушительного Git reset. Откат образа не отменяет миграции состояния и внешние действия. Несовместимые журналы, включая добавление/удаление inbox, требуют согласованной копии остановленного состояния и ручного развёртывания. [Совместимость состояния](config-runtime.md#paths-and-state) объясняет откат к коду без inbox.

## Установка обработчика

Проверка доступна всем клиентам, unattended apply требует Linux/systemd на Compose-хосте. Установи один раз:

```bash
npm run update-runner:install
systemctl --user status opencodebot-update.path
```

Состояние выбирается через `--state-dir`, `OPENCODEBOT_STATE_DIR` процесса, `.env` Compose либо `./state`. Это должен быть источник монтирования `/app/state`. Установщик создаёт user units в `~/.config/systemd/user` и несекретный `updates/runner.json`.

```bash
npm run update-runner:install -- --state-dir /absolute/host/state
npm run update-runner:uninstall
```

Повтори установку при смене репозитория, ветки, checkout или папки состояния. Прямой запуск использует ту же схему либо `OPENCODEBOT_UPDATE_RUNTIME_DIR`, без пути конкретной частной установки.

## Проверка развёртывания

```bash
npm run deploy:bot
npm run health:live
docker compose logs --since=2m opencodebot
```

Health проверяет действующий процесс и обязательные API, не отправляя сообщений. Сверь ревизию образа с коммитом. После публикации `/update` должен показывать актуальность. Не создавай production-коммит ради кнопки: протокол проверяется изолированным smoke, а ближайшее настоящее подтверждённое обновление проверяет полный apply.
