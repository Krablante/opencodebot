# Обновления

[Русский](self-update.md) · [English](../en/self-update.md) · [Указатель](README.md)

Команда `/update` проверяет `main` публичного репозитория вручную. Расписание в публичной конфигурации выключено; чтобы включить его, задайте `updates.enabled: true`, время `updates.checkAt` и часовой пояс IANA `updates.timeZone` в приватном конфиге. Ручная проверка не включает и не сдвигает расписание.

При новой ревизии бот показывает в Telegram текущий и целевой SHA, число коммитов, короткие заметки из диапазона Git, ссылку на сравнение и действия `Update & restart`/`Not now`. Кнопка обновления принимает только показанную точную ревизию. Откладывание скрывает повтор того же предложения до следующего календарного дня заданного часового пояса; при выключенном расписании закрывает только текущую карточку. Коммиты `feat:`, `fix:` и `perf:` видны как отдельные пользовательские заметки, остальные сворачиваются в счётчик обслуживания.

## Граница полномочий

Контейнер бота не получает Docker socket и исходники. Он кладёт атомарный `updates/request.json` в общий каталог состояния; пользовательский `systemd.path` на **Linux-хосте с Compose** запускает фиксированный `scripts/apply-update.mjs`. Результат сохраняется в `updates/status.json`, и новый процесс бота обновляет ту же Telegram-карточку. Runner принимает UUID и полные Git SHA, проверяет чистый fast-forward checkout, ветку и origin, запускает только известные команды, собирает бот с `OPENCODEBOT_BUILD_SHA`, пересоздаёт только его контейнер и проверяет `health:live`. При неудачной замене он пытается вернуть прежний образ и снова проверяет состояние.

Это обновление **не** устанавливает плагин и skill на хосты OpenCodez и не перезапускает OpenCodez. Если диапазон коммитов меняет `plugins/opencodebot-artifacts/` или `skills/telegram-artifact-send/`, карточка явно напоминает об отдельном развёртывании их установленных копий.

Изменение Compose или скриптов хостового runner требует ручного обновления: кнопка применения не показывается. Точно так же runner отвергает переход на код без поддержки долговечного Telegram inbox или обратно — старая версия не восстановит уже принятые в журнал обновления. Источник истины о запущенной версии — SHA из образа, заданный `npm run deploy:bot`, а не JSON-конфиг и не просто HEAD checkout.

## Установка и ручной путь

Для Linux-хоста с Compose установите наблюдатель один раз:

```bash
npm run update-runner:install
systemctl --user status opencodebot-update.path
```

Установщик берёт `OPENCODEBOT_STATE_DIR` из окружения или игнорируемого Compose `.env`; без них используется `./state` в checkout. При особом размещении явно задайте `npm run update-runner:install -- --state-dir /absolute/host/state`. Это должен быть **источник монтирования** `/app/state`. Повторите установку, если изменились ветка, репозиторий, каталог проекта или путь состояния. Удаление: `npm run update-runner:uninstall`. Сам runner требует Linux/systemd; Telegram-клиент и сервер OpenCodez могут работать на Windows или macOS.

При изменении управляющих файлов, первом развёртывании или невозможности применить карточку обновите checkout и запустите:

```bash
git pull
npm run deploy:bot
```

Для изменений Compose-сервисов используйте `npm run deploy:all`. Обе команды требуют чистый checkout и проверяют работающий контейнер после запуска. Если rollback идёт на версию **до** журнала inbox, остановите приём, дождитесь пустой очереди, остановите бот, перенесите контрольный курсор из последней записи журнала в прежнее `runtime.telegramUpdateOffset` в `state.json` и только затем запускайте старый код. Сохраните приватную резервную копию всех трёх файлов состояния до этой процедуры. Обычный откат образа между версиями с поддержкой inbox выполняется runner только в совместимых границах.
