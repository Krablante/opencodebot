# Конфигурация и состояние

[Русский](config-runtime.md) · [English](../en/config-runtime.md) · [Указатель](README.md)

Исходники и общие примеры живут в Git. Токены, адреса ваших серверов и состояние бота остаются в локальных файлах. `npm run init-config` создаёт `config.local.json` и `servers.json` рядом с исходниками, не перезаписывая уже существующие файлы. `config.example.json` описывает публичную форму настроек; автоматические проверки обновлений и необязательные провайдеры в нём выключены.

## Загрузка и секреты

По умолчанию бот читает `config.local.json`; переменная `OPENCODEBOT_CONFIG` задаёт другой путь. Относительные пути в `paths` вычисляются **от каталога файла конфигурации**. `paths.serversJson` указывает на список серверов, `paths.statePath` — на основной файл состояния, `paths.uploadsDir` — на временные загрузки. Если `config.local.json` отсутствует, запуск завершается с ошибкой: публичный пример не подменяет рабочую конфигурацию.

Создайте `token.env` из `token.env.example`. Поместите туда токен BotFather (`OPENCODEBOT_TOKEN`), числовые ID допущенных операторов (`OPENCODEBOT_ALLOWED_USER_IDS`) и пароль OpenCodez (`OPENCODEZ_SERVER_PASSWORD`). При включении дополнений здесь же хранятся `OPENROUTER_API_KEY`, `GROQ_API_KEY`, ключи суммаризации/TTS, токен шлюза артефактов и при необходимости `TELEGRAM_API_ID`/`TELEGRAM_API_HASH`. Значения переменных процесса перекрывают файл токенов. Не публикуйте этот файл и не копируйте секреты в JSON.

`telegram.chatId` закрепляет форум за ботом, `telegram.allowedUserIds` ограничивает управление. Начальная привязка по первому сообщению разрешённого человека работает лишь при `allowChatBootstrap: true`; после неё сохраните ID чата и выключите этот режим. `ui.defaultLanguage` задаёт исходный язык, а команда `/lang` сохраняет последующий выбор в состоянии.

## Серверы и профили

Каждая запись `servers.json` требует уникальные `id` и абсолютный HTTP(S) `url`. Необязательный `home` должен быть абсолютным путём того хоста, где живёт OpenCodez: он задаёт каталог для `/new`, если политика `newSessionDefaultDirectory` равна `serverHome`. `uploadRoot` и `artifactUploadRoot` задают каталоги файлов **на целевом хосте**. Удалённое копирование задаётся `transfer: {"type":"ssh","host":"..."}`; локальный вариант работает, только если процесс бота действительно видит эти пути. Для Windows-цели укажите `pathStyle: "windows"` и подходящий способ передачи. Флаг `offline_ok` исключает сервер из обязательной проверки доступности при live health check.

```json
{
  "servers": [{
    "id": "workstation",
    "url": "http://host.docker.internal:4096",
    "home": "/home/operator",
    "transfer": { "type": "ssh", "host": "workstation" }
  }]
}
```

`opencode.mirrorScope` выбирает `global` (один `/global/event` на сервер, новые сессии из разных каталогов) либо `serverHome` (один `/event` для `home`; тогда `home` обязателен). `defaultPrompt.serverID` выбирает сервер по умолчанию. Именованные `promptProfiles` используются в `/new` и `/reset`. Встроенные профили — это стартовые варианты для Telegram, а не выбор модели для уже существующих веб-сессий:

| Профили | Модель | Варианты |
| --- | --- | --- |
| `d4flash`, `d4pro` | DeepSeek V4 Flash / Pro | max |
| `luna`, `lunah`, `lunamax` | GPT-6 Luna | xhigh / high / max |
| `terra` | GPT-5.6 Terra | xhigh |
| `gpt6`, `gpt6m` | GPT-6 Astra | high / medium |
| `sol`, `solh`, `solm`, `solx`, `solmax` | GPT-6 Sol | high / high / medium / xhigh / max |

Каждый профиль содержит `agent`, `model.providerID`, `model.modelID`, необязательный `model.variant` и `opencodezSystem`. Для систем Sol/Luna нужна версия OpenCodez с соответствующими встроенными System. Локальные записи дополняют или переопределяют встроенные; обновление бота не переписывает явно заданный профиль.

## Файлы и ограничения

`attachments` управляет числом и размерами файлов в запросе. Малые файлы уходят в OpenCodez как data URL; крупные копируются в каталог целевого сервера, а в запрос передаётся путь на этом сервере. Облачный Bot API ограничивает размер скачиваемого файла; для больших файлов нужен локальный Bot API и доступ к его общему каталогу. `artifactUploads.root` задаёт приём файлов из топика артефактов (обычно `~/trash` от `home` выбранного сервера). При локальной передаче внутри Docker конечный путь должен быть смонтирован на запись; [матрица путей](docker.md#каталоги-для-файлов) объясняет это на примерах.

## Расшифровка речи

`speech.enabled` по умолчанию выключен. Для включения задайте хотя бы один ключ провайдера и список моделей в `speech.models` при необходимости. OpenRouter принимает JSON/base64, Groq — multipart. `speech.language` по умолчанию равен `"auto"`; для подсказки распознавателю укажите, например, `"ru"` или `"en"`. `speech.prompt` можно заполнить коротким словарём терминов. Ни GPU, ни локальная модель в контейнере не нужны.

Голосовое сообщение в обычном топике расшифровывается ответом на него и **не** становится запросом к OpenCodez автоматически. `/sounds_here` выбирает отдельный топик для голосовых и аудиофайлов с закреплённым выбором модели; `/sounds_off` освобождает этот топик, не выключая расшифровку голосовых в остальных. Длинный текст разбивается на обычные сообщения Telegram без потери содержимого.

## Дополнительные функции

`finalVoice` по умолчанию выключен: для включения укажите API суммаризации и хотя бы один профиль совместимого TTS. Текстовый финальный ответ отправляется прежде озвучки. Настройка и команды — в [разделе Final Voice](final-voice.md).

`artifacts.enabled` запускает HTTP-шлюз для отправки файлов агентами. Ключ `OPENCODEBOT_ARTIFACT_TOKEN` отделён от токена Telegram. Адрес и порт выбираются в `artifacts.listenHost`/`port`, цель задаётся командой `/artifacts_here`. Подробности и размеры — в [разделе шлюза](artifact-gateway.md).

`updates.enabled` включает расписание только вместе с явными `updates.checkAt` и `updates.timeZone` (IANA). Команда `/update` выполняет проверку вручную и без расписания. `web` помогает строить ссылки на приватный веб-интерфейс; `wireguard` относится только к отдельному Linux-скрипту, не к работе бота.

## Сохранение и восстановление

В `state.json` находятся привязки, настройки панели, выбранные топики, отметки уведомлений и метаданные сессий. Рядом лежат журналы `<statePath>.telegram-inbox.ndjson` и `<statePath>.mirror-markers.ndjson`: первый хранит принятые, но ещё не обработанные обновления Telegram и курсор подтверждения, второй — отметки доставки зеркала. Оба нужны при восстановлении и входят в **приватную резервную копию остановленного бота**. Журнал входящих обновлений временно содержит текст сообщений; не прикладывайте его к отчётам и не удаляйте ради очистки ошибки. При повреждении полного журнального рекорда запуск остановится, чтобы не потерять подтверждённое обновление.

Очередь `/q`, сборка длинного запроса, буфер вложений и активный прогресс живут в памяти и пропадают после рестарта. После отката на версию, которая ещё не понимала журнал inbox, сначала осушите очередь и остановите бот. Сделайте приватную копию состояния, возьмите `offset` из последней полной контрольной записи журнала и запишите его в старое поле `runtime.telegramUpdateOffset` файла `state.json`. Только после этого запускайте старый код: он не умеет восстановить незавершённые записи нового inbox. Такой откат требует отдельного осознанного решения оператора, а не кнопки самообновления.
