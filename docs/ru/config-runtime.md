# Конфигурация и состояние

[English](../en/config-runtime.md) · [Русский](config-runtime.md) · [Все языки](../README.md)

Конфигурация описывает установку: ключи, адреса серверов, пути и доступ к провайдерам. Настройки Telegram описывают работу пользователей: профили, язык, уведомления и выбор тем. После первого импорта редактируй профили в General; изменение исходных профилей в конфигурации не меняет сохранённые предпочтения.

[Первый запуск](first-run.md) объясняет установку, [Docker](docker.md) — монтирование. Здесь собраны параметры и правила хранения. Потоки событий и восстановление описаны в [архитектуре](architecture.md).

## Загрузка

`npm run setup` готовит приватные файлы. `npm run init-config` создаёт `config.local.json` и `servers.json` для ручной настройки. Бот читает `OPENCODEBOT_CONFIG` либо `config.local.json` в репозитории. Отсутствующий файл — ошибка; публичный пример не подставляется автоматически.

Относительные пути считаются от каталога конфигурации. Сначала читается `paths.tokenEnv`, затем переменные процесса перекрывают его значения. Ключам место в приватном env-файле, вне JSON и Git.

| Файл или параметр | Назначение |
| --- | --- |
| `config.example.json` | Публичная форма конфигурации; дополнительные провайдеры и расписание обновлений выключены |
| `config.local.json` | Приватная конфигурация установки |
| `paths.serversJson` | Список серверов, обычно `servers.json` |
| `paths.tokenEnv` | Файл секретов, обычно `token.env` |
| `paths.statePath` | Постоянное состояние, обычно `state/state.json` |
| `paths.uploadsDir` | Временные скачивания Telegram, обычно рядом с состоянием |
| `.env` | Пути хоста и UID/GID для Compose; [переменные монтирования](docker.md#files) |

Compose монтирует приватные файлы в `/app/config.local.json`, `/app/servers.json`, `/app/token.env` и `/app/state`. Конфигурация внутри Docker должна использовать пути контейнера. При обычном запуске Node нужны пути хоста. Это особенно важно, если конфигурация хранится вне репозитория.

## Ключи и доступ

Источник токена Telegram задаётся явно: `telegram.token.env`. ID операторов берутся из массива `telegram.allowedUserIds` либо указанной в нём env-переменной. Пароль OpenCodez ищется по `opencode.passwordEnvNames`. Бот не перебирает посторонние переменные в поисках похожих значений.

```env
OPENCODEBOT_TOKEN=123456:bot-token
OPENCODEBOT_ALLOWED_USER_IDS=123456789
OPENCODEZ_SERVER_PASSWORD=optional-password
OPENCODEBOT_ARTIFACT_TOKEN=separate-random-token
GROQ_API_KEY=optional-transcription-key
OPENROUTER_API_KEY=optional-transcription-key
```

`telegram.chatId` выбирает форумную группу. Если чат не задан, `telegram.allowChatBootstrap=true` привязывает первое сообщение разрешённого пользователя в группе. Для общей установки явно задай группу и операторов. Открытие личного чата бота разрешает уведомления; явное отключение сохраняется.

Ключи из `/setup` хранятся в `provider-secrets.json` рядом с состоянием, с доступом только владельцу. Они перекрывают соответствующий ключ провайдера и исключаются из обновления до записи журнала. Включай этот файл в приватные резервные копии. [Первый запуск](first-run.md#audio) объясняет ограничения ввода через Telegram.

## OpenCodez

Каждому серверу нужны уникальный непустой `id` и абсолютный HTTP(S) `url`. При старте проверяется весь список, а ошибки выдаются вместе.

```json
{
  "servers": [{
    "id": "workstation",
    "url": "http://workstation.local:4096",
    "home": "/home/operator",
    "uploadRoot": "/home/operator/.opencodebot/uploads",
    "artifactUploadRoot": "/home/operator/trash",
    "transfer": { "type": "ssh", "host": "workstation.local" }
  }]
}
```

| Параметр | Значение |
| --- | --- |
| `opencode.mirrorScope` | `global` следит за всеми рабочими папками через один `/global/event` на сервер; `serverHome` использует `/event` в `home` |
| `opencode.newSessionDefaultDirectory` | `serverHome` выбирает домашнюю папку сервера; `none` оставляет выбор OpenCodez |
| `home` | Папка новых сессий и основа для `~/trash`; обязательна при `serverHome` |
| `uploadRoot` | Папка больших вложений промптов на сервере; при отсутствии выводится из `home` |
| `artifactUploadRoot` | Отдельная папка входящих файлов FILES на этом сервере |
| `pathStyle` | Необязательный `posix` или `windows`; пути дисков и UNC распознаются |
| `offline_ok` | Boolean; недоступный необязательный сервер не блокирует проверку развёртывания |
| `transfer.type` | `local` или `ssh`; отсутствие означает запись в локальную файловую систему |
| `transfer.host`, `user`, `port`, `identityFile` | SSH-адрес и дополнительные параметры; порт 1–65535 |

Адрес API и адрес передачи файлов — разные вещи. Контейнер Linux может обращаться к API Windows, но записывать файлы Windows через SSH. См. [правила путей Docker](docker.md#artifact-dropbox-paths). `opencode.baseUrl` — резервный адрес API; реальные подключения берутся из списка серверов.

## Профили запуска

`promptProfiles` и `defaultPrompt` задают исходные настройки. Новая установка получает `sol`, `solm`, `solx` и `d4flash`. Существующая один раз импортирует прежние встроенные и явно заданные профили. Удалённые профили не появляются после рестарта. Дальше коллекцией и основным профилем управляет General.

| Профиль | Провайдер/модель | Reasoning |
| --- | --- | --- |
| `sol` | `openai/gpt-6.1-sol` | `high` |
| `solm` | `openai/gpt-6.1-sol` | `medium` |
| `solx` | `openai/gpt-6.1-sol` | `xhigh` |
| `d4flash` | `deepseek/deepseek-flash` | `max` |

Профиль содержит `agent`, `model.providerID`, `model.modelID`, необязательный `model.variant` и `opencodezSystem`. Встроенному System для Sol нужен OpenCodez `1.18.33+opencodez.1` или новее. Модели и доступные варианты reasoning берутся из каталога выбранного сервера; присутствие модели не гарантирует квоту или оплаченный доступ.

Мастер сохраняет показанные настройки, включая reasoning только для этой темы. Первый промпт и повтор незавершённого запуска используют этот снимок, даже если профиль уже изменён. Модель обновляется и в редакторе OpenCodez, и в запросах Telegram. `/reset` берёт актуальный именованный профиль либо сохранённый снимок, если профиль удалён. Чтобы изменить параметры неудачного запуска, исправь или выбери профиль и явно сбрось тему.

## Вложения

`attachments` находится на верхнем уровне. `enabled`, `maxInlineBytes`, `maxFileBytes` и `maxTotalBytes` управляют приёмом и встраиванием. Обычные пределы: десять файлов, 20 000 000 байт на файл и 60 000 000 на подборку. Небольшие файлы передаются как data URL, большие копируются в `uploadRoot`.

```json
{ "attachments": { "enabled": true, "maxInlineBytes": 20000000,
  "maxFileBytes": 20000000, "maxTotalBytes": 60000000 } }
```

Известные размеры и количество проверяются до скачивания. Фактические скачивания расходуют оставшийся общий лимит, включая файлы, ожидающие текст. В ожидании/очереди сохраняются пути, без base64-копий в памяти; кодирование происходит перед отправкой, а при приёме очередь резервирует бюджет будущего встроенного содержимого. После успешной/неудачной отправки временные файлы удаляются; серверные копии доступны агенту и истории. Ежечасная очистка убирает просроченные отдельные файлы подготовки. Конечные папки и FILES автоматически не очищаются: владелец решает, когда файлы больше не нужны.

Облачный Bot API ограничивает скачивания своим консервативным пределом на файл. Локальный режим допускает большие значения. Увеличение лимита повышает расход диска, а для встроенных файлов — памяти и размера запросов. [Доставка артефактов](artifact-gateway.md) описывает отдельный поток исходящих файлов.

## Расшифровка аудио

`speech.enabled` изначально выключен. Для OpenRouter или прямого Groq включи его и задай хотя бы один ключ. Меню скрывает только модели провайдера без ключа. `/setup` сохраняет Groq-ключ и включает прямой `groq/whisper-large-v3-turbo`, не меняя конфигурацию только для чтения.

```json
{ "speech": { "enabled": true, "defaultModel": "groq/whisper-large-v3-turbo",
  "maxFileBytes": 25000000, "queueConcurrency": 1, "language": "auto" } }
```

`language` принимает код ISO-639-1 либо `auto`/`null`; при автоопределении поле не отправляется провайдеру. `prompt`, `temperature` и `responseFormat` — параметры распознавания. `openrouter` и `groq` содержат адреса и имена env-переменных ключей. В своих `models[]` укажи `id` для сохранённого выбора, `apiProvider` для транспорта и `apiModel` для имени модели у провайдера. Дополнительно доступны `label`, `upstreamProvider`, `price` и настройки на модель.

Голосовые заметки в обычных темах и аудио в AUDIO дают копируемые расшифровки и не отправляются агенту автоматически. За активными задачами могут ждать двадцать записей. При переполнении бот просит отправить запись позже. Ошибки провайдеров показывают HTTP-статус, без тел ответов в Telegram и журналах.

## Дополнительные функции и общие настройки

| Параметр или команда | Назначение |
| --- | --- |
| `telegram.botApi` | Облачный по умолчанию; локальный адрес, общая папка и app credentials описаны в [Docker](docker.md#local-telegram-bot-api) |
| `artifacts`, `artifactUploads` | Адрес/авторизация шлюза и входящая папка; [API и плагин](artifact-gateway.md) |
| `finalVoice` | Доступ установки к провайдерам summary/TTS; [настройки и команды](final-voice.md) |
| `finalNotifications.userIds` | Получатели личных уведомлений; пустой список означает разрешённых операторов |
| `ui.defaultLanguage` | Исходный язык; `/lang eng` и `/lang ru` сохраняют общий выбор |
| `ui.timeZone` | Счётчик ответов за день; затем `updates.timeZone`, затем часовой пояс системы |
| `updates` | Репозиторий/ветка и необязательные `checkAt`/`timeZone`; [обновления](self-update.md) |
| `web.publicBaseUrl`, `privateBaseUrl`, `preferHttp` | Ссылки OpenCodez; приватным адресам нужна доступная LAN/VPN-маршрутизация |
| `wireguard` | Только необязательный помощник хоста; [доступ к браузеру](wireguard.md) |

Режим деталей (`/mode`), включение зеркала, случайные названия, напоминания, глубина контекста, уведомления и голосовые предпочтения хранятся в состоянии. Закрепление промптов, окна восстановления и сбор частей текста используют внутренние консервативные значения.

## Пути и состояние

Резервную копию делай при остановленном боте. Сохрани приватную конфигурацию и env-файлы, состояние ниже, ключи провайдеров при наличии и том локального Bot API. Сохраняй владельца и права. Копирование по одному файлу при работающем боте может смешать разные моменты времени.

| Постоянный файл | Содержимое |
| --- | --- |
| `state.json` | Привязки и отключённая история, ожидающие запуски, профили, названия/значки тем, меню, назначения, ограниченные записи вопросов/уведомлений/напоминаний и статистика |
| `state.json.mirror-markers.ndjson` | ID доставленных пользовательских и агентских сообщений; уплотняется при старте и удалении сессии |
| `state.json.telegram-inbox.ndjson` | Курсор Telegram и незавершённые обновления, включая приватный входящий текст и ссылки на файлы |
| `provider-secrets.json` | Ключи из setup; доступ владельцу |
| `state.json.health.json` | Заменяемый снимок процесса, прогресса и очереди без текста разговоров |
| `updates/` | Запросы и результаты фиксированного обработчика обновлений хоста |

Маркеры сохраняются целиком для не более чем 250 сессий; отдельные сообщения внутри сохранённой сессии не обрезаются. Индексы Set делают повторную проверку доставки независимой от длины истории этой сессии. Список известных сессий ограничен 5 000; сохранённые отключённые привязки всё равно запрещают восстановить остановленную тему через повторное обнаружение.

Журналы принимают только полные записи, заканчивающиеся переводом строки. При старте незавершённый хвост отбрасывается; испорченная полная запись останавливает старт. Сохрани повреждённый журнал для ремонта. Удаление inbox может потерять уже подтверждённую работу. Ошибка записи приёма или завершения останавливает бота; сначала восстанови доступность хранилища.

Сроки активности и курсоры восстановления разделяют отложенную атомарную запись в пределах минуты; при завершении она сбрасывается на диск. Немедленная запись сохраняет и остальные изменения. Ошибка записи состояния сообщается; отложенные записи повторяются через пять секунд. При аварии теряются изменения, не попавшие на диск. См. [гарантии восстановления](architecture.md#recovery-and-limits).

Очередь промптов, сбор частей текста/медиа, личные черновики и незавершённая озвучка находятся в памяти. Очередь допускает 20 задач на сессию, 100 всего и 64 МиБ текста/встроенных файлов. Файлы очереди также занимают диск подготовки. Рестарт сбрасывает эти буферы; получение обновления через inbox не делает их постоянными.

Подтверждённый `404` конкретной сессии удаляет её привязку и связанные записи, сохраняя ожидающий запуск в этой теме. `/reset`, наоборот, оставляет прежнюю историю. Не открывай живое состояние вторым `StateStore.load`: загрузка может мигрировать, уплотнять и записывать файлы.

Для отката к версии без inbox сначала опустоши inbox, останови бота и перенеси `offset` последнего checkpoint в `runtime.telegramUpdateOffset` остановленного состояния. Старый код не восстановит ожидающие записи. При остальных миграциях восстанавливай согласованную резервную копию и предыдущий образ вместе; [обновления](self-update.md) объясняют пределы автоматического отката.
