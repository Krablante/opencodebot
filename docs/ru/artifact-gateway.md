# Шлюз артефактов

[Русский](artifact-gateway.md) · [English](../en/artifact-gateway.md) · [Указатель](README.md)

Один OpenCodeBot хранит токен Telegram и отправляет файлы и текст в **один выбранный топик** артефактов. Плагин на машине агента читает локальный файл и передаёт его байты шлюзу по HTTP с отдельным токеном. Агенту не нужен токен Telegram или доступ к файлам машины бота. Команда `/artifacts_here` выбирает целевой топик; повторная команда в другом топике заменяет старую цель. Топик артефактов не является зеркалом сессии.

## Настройка

В приватном конфиге включите шлюз, а ключ положите в `token.env`:

```json
{
  "artifacts": {
    "enabled": true,
    "listenHost": "0.0.0.0",
    "port": 8788,
    "tokenEnvNames": ["OPENCODEBOT_ARTIFACT_TOKEN"]
  }
}
```

```dotenv
OPENCODEBOT_ARTIFACT_TOKEN=replace-with-a-long-random-token
```

Compose публикует порт `OPENCODEBOT_ARTIFACT_PORT` (по умолчанию `8788`). Оставьте его доступным только доверенным хостам. Перезапустите бот и отправьте `/artifacts_here` в нужном форуме. Ключ шлюза должен быть у бота и у плагина OpenCodez, но **не** заменяет токен Telegram.

## Приём файлов от человека

Файлы, присланные в выбранный топик, сохраняются в `artifactUploads.root` целевого OpenCodez-сервера. Пустая подпись использует сервер по умолчанию; первым словом подписи можно выбрать другой `id` из `servers.json`. Неизвестный сервер отклоняется до скачивания. После ID можно указать имена через запятую в порядке файлов: `workstation photo, backup.tar.gz`. Имя без точки наследует всё расширение исходного файла, включая `.tar.gz`; пропущенная позиция сохраняет исходное имя. Имена очищаются и не создают вложенных каталогов. Путь обычно состоит из `root/YYYY-MM-DD/имя-файла`, а бот возвращает абсолютный путь в Telegram.

При локальной передаче процесс бота должен иметь этот конечный путь на запись. Для Linux/macOS с Docker настройте `OPENCODEBOT_ARTIFACT_UPLOAD_SOURCE` и `OPENCODEBOT_ARTIFACT_UPLOAD_ROOT` так, чтобы каталог хоста и путь внутри контейнера совпали с видимым OpenCodez путём. На Windows-хост для итогового пути `C:\...` проще передавать файлы по SSH или запустить бот напрямую через Node.js; Linux-контейнер не понимает путь с буквой диска сам по себе. Подробности — в [Docker](docker.md#каталоги-для-файлов).

## API шлюза

Каждый запрос требует `Authorization: Bearer <OPENCODEBOT_ARTIFACT_TOKEN>`. `GET /artifacts/status` сообщает, выбран ли топик. `POST /artifacts/send` принимает JSON с `caption`, `text`, `mode` и метаданными; он **не** открывает пути, присланные клиентом. `POST /artifacts/send-file` принимает поток байтов и небольшой base64url JSON в заголовке `X-Opencodebot-Artifact-Meta` с именем файла и MIME-типом. Временный файл создаёт и удаляет сам шлюз.

```json
{
  "caption": "workstation / app / result",
  "mode": "text",
  "text": "Готово: отчёт записан."
}
```

Обычный текст ограничен 3400 символами и итоговым лимитом сообщения Telegram 4096 символов с подписью и путями. При превышении шлюз возвращает HTTP 413 **до отправки**, а не выдаёт обрезанное сообщение за успешное: большой текст отправляйте файлом в режиме `document`. Плагин ограничивает чтение текстового файла в `mode=text` и предлагает `mode=document` для большого файла. В `auto` JPEG/PNG/WebP подходящего размера становятся фотографией; при превышении фото-лимита или отказе Telegram оригинал уходит документом. Облачный Bot API ограничивает файл консервативными 50 MiB; локальный принимает поток до 2 GB и передаёт Telegram путь к своему общему хранилищу.

## Плагин и skill

Плагин лежит в `plugins/opencodebot-artifacts/`. Установите его **на каждом хосте OpenCodez**, где агент должен вызывать `opencodebot_send_artifact({path?, paths?, text?, caption, mode?})`. Передайте ему `OPENCODEBOT_ARTIFACT_GATEWAY_URL` и `OPENCODEBOT_ARTIFACT_TOKEN` через окружение либо через настройки плагина. Относительный путь считается от проекта агента; абсолютные пути и `file://` тоже поддерживаются. Плагин читает файлы там, где выполняется OpenCodez, и посылает в Telegram лишь отображаемую ссылку на исходный путь.

Связанный skill находится в `skills/telegram-artifact-send/`. Устанавливайте каталог целиком, включая `agents/openai.yaml`, и вызывайте отправку только по явной просьбе человека. После обновления исходников плагина или skill обновите их установленные копии и перезапустите затронутые сервисы OpenCodez; самообновление бота их не разворачивает. Проверьте `/artifacts/status`, отправку маленького текста, изображения в `auto` и файла в `document`, затем приём файла от пользователя.
