# Доставка артефактов

[English](../en/artifact-gateway.md) · [Русский](artifact-gateway.md) · [Все языки](../README.md)

FILES работает в двух независимых направлениях. Агент передаёт локальный файл/текст шлюзу бота, который отправляет его в одну выбранную тему. Пользователь Telegram кладёт файл в эту тему, а бот сохраняет его на выбранном сервере OpenCodez. Для доставки агента не нужны SSH и Telegram-токен у агента; входящее удалённое сохранение может использовать SSH.

## Установка

`/setup` готовит FILES, по запросу включает шлюз и показывает URL с персональной карточкой токена артефактов. Установи плагин и полный skill на каждом хосте агента. Подключённый шлюз и доступная для записи входящая папка — разные проверки: проверь оба направления.

Ручная конфигурация:

```json
{ "artifacts": { "enabled": true, "listenHost": "0.0.0.0", "port": 8788,
  "tokenEnvNames": ["OPENCODEBOT_ARTIFACT_TOKEN"] },
  "artifactUploads": { "enabled": true, "root": "~/trash", "dateFolders": true } }
```

Задай длинный случайный `OPENCODEBOT_ARTIFACT_TOKEN` в приватном окружении и выполни `/artifacts_here` в назначении. Команда в другой теме меняет общий получатель и отключает агентскую привязку нового FILES. Обычный текст там показывает инструкции папки. Оставь шлюз в доверенной сети и согласуй listener с [портами/папками Compose](docker.md).

<a id="user-dropped-files"></a>
## Файлы пользователей

Пустая подпись выбирает основной сервер. Первое слово задаёт сервер; неизвестный ID отклоняется до скачивания. Имена через запятую применяются по порядку ко всему альбому:

```text
workstation photo, backup, , report.pdf
```

Имя без точки наследует полный суффикс от первой точки исходника: `backup` для `archive.tar.gz` даёт `backup.tar.gz`. Имя с точкой используется точно. Пустые/недостающие позиции сохраняют исходные имена, лишние игнорируются. Очистка имени не даёт создать подкаталоги. Здесь также действуют пределы количества и фактического размера подборки.

Конечный путь — `artifactUploadRoot` либо `artifactUploads.root` от `home`, необязательная папка `YYYY-MM-DD` и имя. Local требует доступного для записи монтирования; удалённые пути используют transfer сервера. [Docker](docker.md#artifact-dropbox-paths) объясняет Linux/macOS/Windows.

Существующие файлы молча не перезаписываются. Совпадение имени завершается просьбой переименовать; полные local/POSIX передачи публикуют готовый файл атомарно. Если поздний файл подборки не сохранился, ранее успешные остаются. Удалением конечных файлов управляет оператор.

## API шлюза

Всем endpoint нужен `Authorization: Bearer <artifact-token>`. `GET /artifacts/status` показывает готовность назначения. `POST /artifacts/send` принимает JSON текста/подписей до 64 КиБ:

```json
{ "caption": "workstation my-app deploy log", "mode": "text", "text": "log excerpt" }
```

Файлы идут потоком байтов, без JSON-путей и base64:

```text
POST /artifacts/send-file
Content-Type: application/octet-stream
X-Opencodebot-Artifact-Meta: <base64url JSON>

<raw bytes>
```

Пример декодированных метаданных:

```json
{ "caption": "workstation my-app screenshot", "mode": "auto",
  "file": { "filename": "screen.png", "contentType": "image/png" } }
```

Пути клиента — только подписи. Владение подготовкой хранится внутри процесса, поэтому JSON не может запросить чтение файла или произвольную очистку. Файл пишется в уникальный каталог с выбранным basename. Завершение/ошибка удаляет его; опознанные брошенные папки старше суток удаляются ежечасно.

| Режим или предел | Поведение |
| --- | --- |
| `auto` | Подходящие JPEG/PNG/WebP как фото, остальные как документы |
| `photo` | Предпочтение отображения; большое/отклонённое фото идёт документом без потерь |
| `document` | Файл без потерь |
| `text` | Сворачиваемая цитата; обычный текст, если экранирование превышает предел |
| Текст | 3 400 символов, с общим пределом подписи/путей/сообщения 4 096 |
| Облачные файлы | Приём до 50 МиБ, с пределом 32 МиБ памяти при отправке из подготовки в multipart |
| Локальные файлы | До 2 ГБ Bot API, отправка по пути общей папки |
| Одновременная работа | Четыре передачи; превышение даёт `503` и `Retry-After: 5` |

Большой текст отклоняется до доставки файла. Отправляй его документом. Успех возвращает ID и ссылки сообщений; при неоднозначной сетевой ошибке проверь тему до повтора.

## Плагин OpenCodez

Установи `plugins/opencodebot-artifacts/` как пакет через процесс развёртывания OpenCodez. Укажи установленную папку абсолютным/относительным путём, `file://` URL или парой `[spec, options]`. Windows принимает обычный абсолютный путь либо `file:///C:/...`.

```jsonc
{ "plugin": [["/path/to/opencodebot/plugins/opencodebot-artifacts",
  { "gatewayUrl": "http://gateway-host:8788" }]] }
```

Храни токен в приватном окружении хоста:

```env
OPENCODEBOT_ARTIFACT_GATEWAY_URL=http://gateway-host:8788
OPENCODEBOT_ARTIFACT_TOKEN=same-private-artifact-token
```

Инструмент: `opencodebot_send_artifact({ path?, paths?, text?, caption, mode? })`. Относительные/POSIX/Windows/UNC пути и file URL разрешаются на хосте агента. Несколько путей дают подборку с читаемыми подписями. Сам шлюз не читает файловую систему агента.

## Установка skill

Копируй всю папку `skills/telegram-artifact-send/`, включая `agents/openai.yaml`. Skill срабатывает только на явную просьбу отправить в Telegram/TG/artifacts. «Прочитай файл» и «покажи лог» сами по себе ничего не отправляют.

<a id="updating"></a>
## Обновление

Обнови бота через `git pull --ff-only` и `npm run deploy:bot`, либо `deploy:all` при изменении сервисов. Изменение plugin/skill требует обновить установленные копии на каждом затронутом хосте OpenCodez и перезапустить их сервис. Бот сообщает об этом шаге и не перезапускает OpenCodez.

Проверь небольшой текст, фото, документ без потерь, fallback большого/отклонённого фото и входящий файл со сверкой байтов. Повтори имя существующего файла и проверь его сохранность. Используй одноразовые назначения, сохраняя настоящие данные FILES.
